# Implementation Plan: Unified Master Chart & Role Notes

**Branch**: `002-master-chart-role-notes` | **Date**: 2026-05-31 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-master-chart-role-notes/spec.md`

---

## Summary

Replace six per-role chart text fields with a single `master_chart` field per song, and add a `notes` table for role-scoped annotations anchored to chart lines. The scroll engine continues to broadcast absolute pixel positions unchanged — notes render in the DOM flow but are never scroll targets, so sync fidelity is preserved regardless of each device's note visibility setting.

---

## Technical Context

**Language/Version**: TypeScript 5.x (frontend and backend)
**Primary Dependencies**: React 18, Vite 5, Socket.IO 4.x, better-sqlite3 9.x, Vitest 2.x, dnd-kit 6.x
**Storage**: SQLite via better-sqlite3 — `notes` table added; `master_chart` column added to `songs`
**Testing**: Vitest (Node environment for server, jsdom for client); real in-process Socket.IO for integration tests
**Target Platform**: Local WiFi PWA — Mac Mini host, mobile browsers
**Project Type**: Full-stack web application (monorepo: client/, server/, shared/)
**Performance Goals**: Note add/update/delete syncs to all clients within 1 second; chart render with 20 notes shows no perceptible lag on mid-range mobile
**Constraints**: Offline-capable (PWA service worker); zero external runtime calls; 50px drift tolerance after 5 minutes of auto-scroll
**Scale/Scope**: 2–8 members, ~20 songs, ~50 notes per song maximum

## Technology Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Note storage | Separate `notes` table | Atomic sync per note; avoids JSON blob race conditions |
| Line indexing | Integer stored, computed from `\n` split | Simple, deterministic, consistent across all clients |
| Blank line handling | Count all lines (including blank) | Preserves author intent; index stability |
| Notes in state_sync | Current song's notes only | One round-trip join; proportional payload |
| Migration strategy | Add column, keep legacy columns as NULL | SQLite DROP COLUMN complexity avoided |
| Note sync | Delta events (note_added/updated/deleted) | Consistent with spec 001 pattern; minimal bandwidth |
| Note ownership | Role-scoped (any member of role can edit/delete) | No persistent user identity; trust-network context |
| Scroll protocol | Unchanged (absolute pixel broadcast) | Notes in DOM flow absorbed by receiver's direct scrollTop assignment |
